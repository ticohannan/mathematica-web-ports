### [Title]
Probabilistic Roadmap Method

### [Section]
Caption<<PaneSelectorBox>>

### [Text]
\<This Demonstration uses the probabilistic roadmap method (PRM) to connect configurations from an initial configuration (shown by a Locator) to a goal configuration. First, click the button "add 50 vertices" to randomly sample configurations and calculate if they collide with obstacles (red) or are safe (green). Next, select a "radius" value to try and connect safe vertices less than the radius distance into a roadmap. If a path from the initial to the goal configuration is found, it can be traversed using the "progress" slider. Although the PRM does not need to calculate the configuration space obstacles, you can make them visible by clicking the checkbox.\>

### [Input] (init)
(* test if point pt is inside convex polygon poly *)
ptInPoly[poly_,pt_]:=
			(* translate poly such that pt becomes the origin *)
			poly//#-pt&/@#&//
			(* pt is inside if adjacent vertex vector pair angles are all positive or all negative *)
			{#,RotateLeft@#}&//Transpose//angtest@@#&/@#&//Equal@@#&
ptInPolys[polys_,pt_]:=Or@@(ptInPoly[#,pt]&/@polys) 

### [Input] (init)
(*Is point pt inside list of polygons polys?*)
pathOK[ps_,pe_,polys_,delta_]:=Module[{dist,n,pt},
dist = Norm[ps-pe]; (*Primitive collision checking that checks every delta distance along a line from ps to pe for collisions with polygons. *)
If[dist<= delta,
True,
n=Ceiling[dist/delta];
!Or@@Table[pt = ps+ (pe-ps)*(i)/(n+1);
ptInPolys[polys,pt],{i,1,n}]]
]

### [Input] (init)
pathOKT[ps_,pe_,polys_,delta_]:=Module[{dist,n,pt,dx,dx2,dy,dy2},
(*Primitive collision checking that checks every delta distance along a line from ps to pe for collisions with polygons, uses toriod assumption. *)
(*toroid assumption*)
dx = Abs[pe[[1]]-ps[[1]]];
dx2 =2π- dx;
dy = Abs[pe[[2]]-ps[[2]]];
dy2 =2π-dy ; 

dx=pe[[1]]-ps[[1]]+If[dx<dx2,0, If[pe[[1]]>ps[[1]],-2π,+2π]];
dy=pe[[2]]-ps[[2]]+If[dy<dy2,0, If[pe[[2]]>ps[[2]],-2π,+2π]];

dist = Sqrt[dx^2+dy^2];
If[dist<= delta,
True,
n=Ceiling[dist/delta];
!Or@@Table[pt = ps+ {dx,dy}*(i)/(n+1);
If[pt[[1]]<0,pt[[1]]=pt[[1]]+2π];
If[pt[[1]]>2π,pt[[1]]=pt[[1]]-2π];
If[pt[[2]]<0,pt[[2]]=pt[[2]]+2π];
If[pt[[2]]>2π,pt[[2]]=pt[[2]]-2π];
ptInPolys[polys,pt],{i,1,n}]]
]

### [Input] (init)
toroidDist :=(* Toroid assumption, wraps from 2π to 0. *) (\[Sqrt](Min[(#1[[1]]-#2[[1]])^2,(2π-Abs[#1[[1]]-#2[[1]]])^2]+Min[(#1[[2]]-#2[[2]])^2,(2π-Abs[#1[[2]]-#2[[2]]])^2] )&)

### [Input] (init)
myAstar[adjL_,verts_,si_,fi_]:=Module[{openSet,cameFrom,gScore,fScore,current,currentfscore,path,tentativegScore},
(*Computes A-star shortest path from start node si to final node fi. The set of discovered nodes that may need to be (re-)expanded.
Initially, only the start node is known.*)
openSet={si};
cameFrom= ConstantArray[-1, Length[verts]]; 
(*For node n, cameFrom[n] is the node immediately preceding it on the cheapest path from start to n currently known.*)
gScore = ConstantArray[∞, Length[verts]]; (*For node n,gScore[n] is the cost of the cheapest path from start to n currently known.*)
gScore[[si]] = 0;
(*For node n, fScore[n]:=gScore[n]+h(n).*)
fScore= ConstantArray[∞, Length[verts]]; (*Map with default value of infinity.*)
fScore[[si]]=toroidDist[verts[[si]] , verts[[fi]]];
While[Length[openSet]>0 (*&& ctr<10*),
(*current:=the node in openSet having the lowest fScore[] value*)
currentfscore = Min[fScore[[openSet]]];
current =openSet[[ First@@Position[fScore[[openSet]],currentfscore]]];

If[ current == fi,
path = {fi};While[First@path!=si,PrependTo[path,cameFrom[[First@path]]]];
Return[path]
];
openSet = DeleteCases[openSet,current];
Table[
tentativegScore = gScore[[current]]+toroidDist[verts[[current]],verts[[nbr]]];
If[tentativegScore< gScore[[nbr]],
                (*This path to neighbor is better than any previous one. Record it!*)
cameFrom[[nbr]]=current;
gScore[[nbr]]=tentativegScore;fScore[[nbr]]=gScore[[nbr]]+toroidDist[verts[[nbr]] , verts[[nbr]]];
If[ FreeQ[openSet,nbr],AppendTo[openSet,nbr]]];
,{nbr,adjL[[current]]}];
];	
Return[-1] (*Failure*)
]

### [Input] (init)
toroidLines[pts_,color1_:Blue,color2_:-1]:=
Table[toroidLine[e,color1,color2], {e,pts}]

### [Input] (init)
toroidLine[e_,color1_:Blue,color2_:-1]:=Module[{dx,dx2,dy,dy2},
dx = Abs[e[[2,1]]-e[[1,1]]];
dx2 =2π- dx;
dy = Abs[e[[2,2]]-e[[1,2]]];
dy2 =2π- dy ;
If[dx>dx2 || dy>dy2,
dx =e[[2,1]]-e[[1,1]]+If[dx<dx2,0, If[e[[2,1]]>e[[1,1]],-2π,+2π]];
dy =e[[2,2]]-e[[1,2]]+If[dy<dy2,0, If[e[[2,2]]>e[[1,2]],-2π,+2π]]; {color1,Line[{e[[1]],e[[1]]+{dx,dy}}],Line[{e[[2]],e[[2]]-{dx,dy}}]},{If[-1===color2,color1,color2], Line[e]}]
]

### [Input] (init)
toroidPt[e_,frac_]:=Module[{dx,dy,dx2,dy2,dist,pt},
dx = Abs[e[[2,1]]-e[[1,1]]];
dy = Abs[e[[2,2]]-e[[1,2]]];
dx2 =e[[2,1]]-e[[1,1]]+If[dx<2π- dx,0, If[e[[2,1]]>e[[1,1]],-2π,+2π]];
dy2 =e[[2,2]]-e[[1,2]]+If[dy<2π- dy ,0, If[e[[2,2]]>e[[1,2]],-2π,+2π]];
dist =Sqrt[dx2^2+dy2^2];
If[dist==0,pt=e[[1]],
pt=e[[1]]+frac{dx2,dy2};
pt[[1]] =pt[[1]]+If[pt[[1]]>2π,-2π,If[pt[[1]]<0,2π,0]];
pt[[2]] =pt[[2]]+If[pt[[2]]>2π,-2π,If[pt[[2]]<0,2π,0]];
];
pt
]

connectPoints[goodPts_,edgesNNadjin_,polys_,delta_,edgesNNin_, point2start_,r_]:=
Module[{ps,pe,pei,
edgesNNadj,
edgesNN
},
edgesNNadj=edgesNNadjin;
edgesNN=edgesNNin;
Table[
ps = goodPts[[i]];
Table[
pei = Position[goodPts,pe,1,1][[1,1]];
(*if pei is not in edgesNNadj[[i]] *)
If[ Count[edgesNNadj[[i]],pei]<1,
If[pathOKT[ps,pe,polys,delta], 
AppendTo[edgesNN,{ps,pe}];
AppendTo[edgesNNadj[[i]],pei];

] ,{pe,Quiet[Nearest[Drop[goodPts,{i}],ps,{10,r},DistanceFunction->toroidDist]]}],
 {i,point2start,Length[goodPts]}];
{edgesNNadj,edgesNN}
]

### [Text]
The goal of robot motion planning is to find a continuous path from an initial configuration to a goal configuration that is collision-free. A configuration is a complete specification of every point on the robot. This Demonstration assumes the configuration of the robot is specified by two angles, each from 0 to 2π. The resulting configuration space is shaped like a toroid, and so wraps from 2π to 0 on the edges of the plot shown. Obstacles in the robot's workspace map to obstacle regions in the configuration space, but computing these regions is computationally expensive. 

### [Text]
\<Instead, the probabilistic roadmap method (PRM) attempts to solve the motion planning problem by building a graph that represents the connectivity of the configuration space. This avoids the need to explicitly compute the configuration space obstacles, and changes the motion-planning problem into a graph-search problem. It requires (a) being able to determine whether a configuration is in collision with any obstacle; and (b) a "local planner" that can quickly determine if two configurations can be joined by a collision-free path. Typically this local planner checks if a straight-line path in the configuration space is possible.\>

### [Text]
The PRM has three parts: 

### [Text]
\<(1) Generate random points in the configuration space and calculate if they are in the free configuration space (green points) or in collision with obstacles (red points). \>

### [Text]
\<(2) Attempt to connect points in the free configuration space to their nearest neighbors less than radius distance apart using the local planner. Parts (1) and (2) generate the roadmap. \>

### [Text]
\<(3) The local planner attempts to connect the initial configuration to the nearest point in the roadmap and the goal configuration to the nearest point in the roadmap. Then a graph search is used (A* search in this Demonstration) to find the shortest path in the roadmap.\>

### [Text]
\<PRM was developed in 1996 by Lydia Kavraki et al. [1]. PRMs generate a roadmap that can be reused for subsequent motion planning queries. PRM was designed for high-dimension configuration spaces (dimensions of five or more), but this Demonstration uses two dimensions for ease of visualization.\>
