### [Title]
Breadth-First Search Robot Motion Planning

### [Section]
Caption<<PaneSelectorBox>>

### [Text]
This Demonstration shows a resolution-complete planner that finds the shortest path between an initial and final configuration of a two-link, planar-arm robot by using a breadth-first search. The robot operates in the workspace on the left that contains two small circular obstacles. The corresponding robot phase space on the right shows the configurations q=(Subscript[Theta, 1],Subscript[Theta, 2]), for which an arm intersects an obstacle. You can relocate obstacles in the workspace and change the initial and final positions. You can improve the resolution of the search grid by increasing Q and move the robot along the shortest path by increasing P.

pointsegdis2[{seg_,pointlist_}]:=Module[{u=Subtract@@seg,mean=Plus@@seg/2.0},Min[EuclideanDistance[#,(mean-u Sign@# Min[1.0,Abs@#]/2.0)&@(-(2.0 (#-mean).u)/u.u)]&/@pointlist]];

bfsTorus[cSpace_, start_]:=
(*The function below takes a table cSpace and a vertex start {row,col} and performs a breadth first search of cSpace starting
at start. The function returns two lists 
(i) parent, which contains parent pointers representing the breadth first search tree,and 
(ii) lvl, which contains the distances of vertices from start.*)
Module[{d=Dimensions[cSpace],
v, queue={start},
parent,lvl},
parent=Table[{0.0,0.0},{d[[1]]},{d[[2]]}];
lvl=Table[(*10.0*d[[1]]d[[2]]*)Infinity,{d[[1]]},{d[[2]]}];
lvl[[start[[1]],start[[2]]]]=0.0;
While[queue!={},
{v,queue}={First[queue],Rest[queue]}; (*v = {r,c}*)
Table[Module[{r,c,mylc=lvl[[v[[1]],v[[2]]]]+1.0},( (*Add the cells above, left, right and below*)
{r,c}=coords+v;
(*apply the 4 torus conventions*)
If[r<1,r = d[[1]]];If[r>d[[1]], r = 1];
If[c<1,c = d[[2]]];If[c>d[[2]], c = 1];
If[ cSpace[[r,c]]>-0.5\[And]lvl[[r,c]]>mylc,
parent[[r,c,;;]]=v;
lvl[[r,c]]=mylc;
AppendTo[queue,{r,c}]]
)],{coords,{{1,0},{0,1},{-1,0},{0,-1}} }];
Table[Module[{r,c,mylc = lvl[[v[[1]],v[[2]]]]+1.41},( (*add the cells to the diagonals*)
{r,c}=coords+v;
(*apply the 4 torus conventions*)
If[r<1,r = d[[1]]];If[r>d[[1]], r = 1];
If[c<1,c = d[[2]]];If[c>d[[2]], c = 1];
If[ cSpace[[r,c]]>-0.5\[And]lvl[[r,c]]>mylc,
parent[[r,c,;;]]=v;
lvl[[r,c]]=mylc;
AppendTo[queue,{r,c}]]
)],{coords,{{1,1},{-1,1},{-1,-1},{1,-1}} }];
];(*some error checking*)
{parent,lvl}]/;(1<=start[[1]])\[And](start[[1]]<=Dimensions[cSpace][[1]])\[And](1<=start[[2]])\[And](start[[2]]<=Dimensions[cSpace][[2]])


getShortestPath[parents_,start_,end_]:=Module[(*path planning.  parents is a 2D array containing the coordinates for the parents of the cell start. We start the search at the cell 'end' *)
{ps = end,path={end}},
If[parents[[ps[[1]],ps[[2]]]]!={0,0},
While[start != ps,ps = parents[[ps[[1]],ps[[2]]]];AppendTo[path,ps]]];
Return[path]];

### [Text]
The set of all possible configurations of a two-link, planar-arm robot can be represented in a two-dimensional phase space. Of particular interest are the configurations in which the robot collides with one of the obstacles. A resolution-complete planner returns a path between the initial and final configuration if it exists or returns that such a path is impossible. The path is discovered using breadth-first search in the phase space, which calculates the distance to every configuration reachable from the initial configuration. In this Demonstration, path distance is shown by a gradient that darkens with distance from the initial configuration. Even if configurations are close in the configuration space, obstacles may make moving between them require a longer distance.

### [Text]
This Demonstration computes the obstacle regions using 16Q unit squares and determines if the centroid of each square is in a collision. Given Subscript[Theta, 1] and Subscript[Theta, 2], one collision computation is trivial.

### [Text]
\<However, computing the phase-space obstacle region is more difficult because the size of the space representation grows exponentially with the number of degrees of freedom (independent joints) of the robot.\>

### [Text]
Consider how many n-dimensional unit squares are required to fill a space of size k. For a one-dimensional space, k^1 units are needed. For a two-dimensional space, k^2 squares are needed. For an n-dimensional space, k^n hypercubes would be required. The number of collision computations grows exponentially with the number of joints in the robot, making breadth-first search computationally infeasible for robots with many joints.

### [Text]
The phase space for a two-link, planar robot can be represented on a torus. When rotation joint 1 moves past 2π, it returns to angle 0. This is represented by dashed and solid lines of the same color. If the phase space were printed on a rubber sheet and cut out and the dashed and solid lines of each color were joined, the resulting shape would be a torus. In this Demonstration, moving the locator past the edge of the phase space wraps the angle around 2π.
