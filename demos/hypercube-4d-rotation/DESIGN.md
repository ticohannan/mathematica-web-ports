## 1. Purpose and background

The Demonstration shows a hypercube (tesseract) turning in four dimensions, projected to 3D. A rotation in 4D keeps a
whole plane fixed; the six coordinate planes give six independent rotations, each with its own Animator. The 16
vertices (±1, ±1, ±1, ±1) are turned, moved by 2 along w and divided by 1 + pw (w + 2): a central projection whose
strength the slider "stereographic projection" sets. The outer cube of the picture is the cube w = −1, the inner one
w = +1; the faces are coloured by vertex (blue, red, green, yellow for the four groups of four vertices), shown in one
blue, or left out (edges only). From the caption: "The axis (set of fixed points) in a 4D rotation is a plane. As a
simple example, stop the animation and set all the angles to zero. Drag the first slider; this rotates the hypercube
without distortion about the W-X plane, which we see in 3D as a rotation about the X axis."

## 2. Scope

In scope: every control of the original (three radio-button bars and a checkbox, three sliders, six Animators with
their play/pause, direction and reset buttons, the angle column, the "reset rotations" button) and its picture. Out of
scope: anything the original does not do; port additions are the A- features.

## 3. Users and use cases

- UC-HY-01: a student watches the hypercube turn in 4D and stops it to study one rotation at a time.
- UC-HY-02: a student compares the six rotations: the three with a fixed plane through w (W-X, W-Y, W-Z) turn the 3D
  picture rigidly, the other three move the inner cube through the outer one.
- UC-HY-03: a student compares the projections: pw = 1 (strong perspective, the inner cube half the outer one) down to
  pw = 0.001 (almost parallel: both cubes the same size).

## 6. Design

- `model.js`: the original's definitions in its order — `Rxw` … `Ryz`, `Transw`, `Proj`, `ProjRot`, the colours
  `c1` … `c4`, `V`, `edge`, `cf`, `allface`, `deleteface` — and `evaluate(state)` → `{ view, graphics }` with the body's
  `coord`, `pts`, `lines`, `dfig` and `Show[coord, dfig]` as `shared/graphics3d.js` data. Plain JavaScript arithmetic
  (simple mode); `Chop` with Mathematica's tolerance 10⁻¹⁰. `view`: the projected vertices, VP, the number of faces,
  ptr1, ptr2, opt1 and the six angle texts.
- `main.js`: one `Manipulate({…})`: the controls in Mathematica's form (RadioButton, Slider, Checkbox, Animator with a
  `DefaultDuration` that reads `dur` from the state); the Grid of the rotations as six rows (`Row`), the angle column
  written by `after`; `View3D` with `onCreate` replacing the viewer's lights by one white ambient light (the original's
  `Lighting`), linear colour output (colours shown as given).
- The faces: `GraphicsComplex[vertices, Polygon[face], VertexColors -> cf]` is written as the shared `plotSurface`
  primitive (indexed triangles with vertex colours, two-sided, `Opacity[op]`; N-HY-02); `EdgeForm[{Black,
  AbsoluteThickness[3]}]` as black 3 px lines (`Thick`, the renderer's 3 px) along the sides of each square.

## 7. Deviations (D), quirks kept (Q), known issues (K) and notes (N)

- D-HY-01: the controls look like the layer's: labels above the sliders, editable value fields (the original's duration
  value is a plain `Dynamic[dur]`), the Grid of the rotation controls as rows with a one-line header; the Animators'
  progress sliders are 80 px wide (ImageSize -> Tiny) and their buttons are the shared Animator's (▶/❚❚, ⏮, → ← ↔).
- D-HY-02: the view angle is 18.5° widened by the factor 1.045 (tan of the half angle): Mathematica pads the plot
  range, and with the plain angle the port's picture was 4.5 % larger than snapshots 1 and 4; with the factor the
  hypercube's width and height agree with all five snapshots within 0.6 %.
- D-HY-03: under `Opacity[0]` (axes unchecked) the axes are not drawn at all: the shared lines at opacity 0 would still
  hide what is behind them (white streaks across the faces), so `after` makes them invisible; the X, Y, Z labels (3D
  text ignores Opacity) are replaced by invisible lines to their positions. The plot range still contains them, as in
  Mathematica, where the invisible axes set the size of the picture (Q-HY-01).
- D-HY-04: the translucent faces are one mesh whose triangles are listed far to near along the ViewPoint (model.js
  `facesPrim`) and blended in that order; Mathematica sorts the polygons for the current view (K-HY-01).
- Q-HY-01: the axes count in the plot range even when they are invisible: the picture's scale is set by ±(2 − pw), so
  that the hypercube keeps about the same size on the screen while pw changes (kept; the snapshots show it).
- Q-HY-02: "edges only" draws all 32 edges whatever the hypercube choice (`lines` does not use `face`), as snapshot 4
  (1 hole, edges only) shows.
- Q-HY-03: the button "reset rotations (with animations stopped)" sets the six angles to 0 but does not stop the
  Animators; a running one continues from 0 (the label asks the reader to stop them first).
- Q-HY-04: the heading "stereographic projection" names a central projection that is not stereographic (E-HY-01).
- K-HY-01: from view directions far from the opening one, the blending order of the translucent faces is not back to
  front: some faces may look darker or lighter than in Mathematica (M-HY-06).
- N-HY-01: `Delete[allface, {}]` (hypercube "full") deletes nothing: snapshot 1 shows all 24 faces.
- N-HY-02: the shared `GraphicsComplex` has no `VertexColors`, so the faces are written as the shared `plotSurface`
  primitive (the data Plot3D makes, drawn with vertex colours); normals are not needed under ambient light. A
  `VertexColors` option for `GraphicsComplex` polygons in `shared/graphics3d.js` would make this unnecessary (shared
  candidate).
- N-HY-03: the checkbox `{0, 1}` stores True/False in the port (the layer's checkbox); the body tests `axe == 1` as a
  number, so True and 1 give the same picture.
- N-HY-04: `DefaultDuration -> dur` is read from the state at every frame, so a new duration changes the speed of a
  running Animator at once; whether Mathematica's Animator does the same is M-HY-05.
- N-HY-05: "Initial settings" restores the controls' initial values (all angles 0, as the control specifications say);
  the notebook's stored Manipulate values (c = d = 1.045, golden `specs`) are values of the running animations when
  the notebook was saved, not initial settings.
